   176→    /**
   177→     * Returns true if the village has already been built (the spirit vein
   178→     * centerpiece block is present above the spawn point).
   179→     *
   180→     * <p><b>CRON-COMPLETIONIST-69 — provenance-aware rebuild guard.</b>
   181→     * If the player (or simulation) has recorded a delta at the centerpiece
   182→     * position — e.g., the player broke the spirit-vein stone — this method
   183→     * returns {@code true} (village was built, then edited; don't rebuild).
   184→     * Without this guard, breaking the centerpiece would cause the next
   185→     * server-start or {@code /ergenverse build} to re-place the centerpiece,
   186→     * undoing the player's edit. See

   189→    public static boolean isAlreadyBuilt(ServerLevel level) {
   190→        BlockPos center = getVillageCenter(level);
   191→        BlockPos markerPos = center.above();
   192→        // 1. Marker present → already built (canon state).
   193→        if (level.getBlockState(markerPos).getBlock() == ErgenverseBlocks.SPIRIT_VEIN_STONE.get()) {
   194→            return true;
   195→        }
   196→        // 2. Player/sim delta at marker → was built, then edited → don't rebuild.
   197→        if (dev.ergenverse.runtime.materialize.ProvenanceAwareRebuildGuard.shouldSkipRebuild(markerPos)) {
   198→            return true;
   199→        }
   200→        // 3. No marker, no delta → never built → rebuild.
   201→        return false;
   202→    }

   204→    // ── Chunk-scoped build infrastructure (CRON-COMPLETIONIST-62) ────────
   205→    //
   206→    // The chunk-materializer invokes buildForChunk(level, bounds) for EACH
   207→    // chunk that overlaps the village footprint. The ThreadLocal CURRENT_BOUNDS
   208→    // holds the active bounds during a buildInternal() call; the sb() helper
   209→    // checks it and skips any placement outside the bounds. When bounds is null
   210→    // (full-build path — commands, login events, SpawnEventHandler), no
   211→    // filtering occurs and every setBlock lands.
   212→    //
   213→    // Why ThreadLocal rather than threading bounds through 14 sub-methods:
   214→    // the village build tree (flattenTerrain, buildRoads, buildCentralPlaza,
   215→    // buildPerimeterFence, buildWangFamilyHome -> buildWangLinCorner, ...) has
   216→    // 79 setBlock call sites and a deep call hierarchy. Adding a ChunkBounds
   217→    // parameter to every method would touch every signature and obscure the
   218→    // geometric intent. The ThreadLocal is set once at the top of buildForChunk
   219→    // and read by sb() at each leaf placement — a single global per build pass.
   220→    //
   221→    // Thread-safety: chunk materialization is single-threaded on the server
   222→    // tick thread, so there is no contention. The ThreadLocal guards against
   223→    // re-entrancy only if a builder were to call another builder (which it
   224→    // does not today).
   225→
   226→    /**
   227→     * The active chunk bounds during a buildInternal() pass, or null if the
   228→     * full village is being built (no filtering).
   229→     */
   230→    private static final ThreadLocal<ChunkBounds> CURRENT_BOUNDS = new ThreadLocal<>();
   231→
   232→    /**
   233→     * Filtered setBlock — the ONLY block-placement call site in this class.
   234→     * Three guards, in order:
   235→     *
   236→     * <p><b>1. Chunk filter (CRON-COMPLETIONIST-62):</b> if CURRENT_BOUNDS is
   237→     * non-null and (x, z) falls outside the bounds, skip. This is what makes
   238→     * buildForChunk chunk-scoped: ~80K candidate placements collapse to ~256
   239→     * actual level.setBlock calls per chunk.
   240→     *
   241→     * <p><b>2. Provenance-aware rebuild guard (CRON-COMPLETIONIST-63):</b> if
   242→     * CURRENT_BOUNDS is non-null (i.e. we are in the chunk-materializer path),
   243→     * consult the {@link WorldDeltaStore} for a PLAYER or SIMULATION delta at
   244→     * (x, y, z). If either exists, skip the placement. The player's edits
   245→     * (and the simulation's edits) take priority over CANON — re-placing a
   246→     * CANON block on top of a player edit would be a wasted write (the
   247→     * materializer replays the player/sim delta afterward and restores the
   248→     * player's state, but the intermediate write is unnecessary and produces
   249→     * a visible flicker). This guard is the operational realization of the
   250→     * Provenance contract: PLAYER &gt; SIMULATION &gt; CANON.
   251→     *
   252→     * <p>The provenance guard is <b>only active in the chunk-scoped path</b>
   253→     * (CURRENT_BOUNDS != null). The full-build path — {@link #build}, used by
   254→     * SpawnEventHandler at server-start and ErgenverseCommand for manual
   255→     * rebuild — does NOT consult the delta store, because (a) at server-start
   256→     * there are no player deltas yet, and (b) the /ergenverse build command
   257→     * explicitly wants a full rebuild regardless of player edits.
   258→     *
   259→     * <p><b>3. Placement:</b> if both guards pass, call level.setBlock.
   260→     *
   261→     * <p>Y is intentionally not chunk-filtered — structures are vertically
   262→     * thin. Y IS used for the provenance check (deltas are 3D-positioned).
   263→     *
   264→     * <p>Performance: ~50ns per guard (2x O(1) HashMap lookup + PackedPos.pack).
   265→     * For ~256 blocks per chunk-load: ~12.8µs total. Negligible vs the ~1-5µs
   266→     * per saved level.setBlock call.
   267→     */
   268→    private static void sb(ServerLevel level, BlockPos pos, BlockState state, int flags) {
   269→        ChunkBounds b = CURRENT_BOUNDS.get();
   270→        if (b != null) {
   271→            // Guard 1: chunk filter.
   272→            if (!b.contains(pos.getX(), pos.getZ())) return;
   273→            // Guard 2: provenance-aware rebuild guard.
   274→            // If the player or simulation has touched this position, the
   275→            // CANON placement would be overwritten by the materializer's
   276→            // delta replay anyway — skip the wasted write.
   277→            if (hasPlayerOrSimulationDelta(pos)) return;
   278→        }
   279→        level.setBlock(pos, state, flags);
   280→    }
   281→
   282→    /**
   283→     * Provenance-aware guard helper (CRON-COMPLETIONIST-63). Returns true if
   284→     * a PLAYER or SIMULATION delta is recorded at {@code pos}. O(1) per call.
   285→     *
   286→     * <p>Defensive: returns false (no delta → proceed with placement) if the
   287→     * WorldRuntime is not yet initialized. The chunk-materializer already
   288→     * gates on {@code runtime.isInitialized()} so this should never fire in
   289→     * the materializer path, but defense-in-depth protects against unexpected
   290→     * call sites.
   291→     */
   292→    private static boolean hasPlayerOrSimulationDelta(BlockPos pos) {
   293→        try {
   294→            WorldRuntime runtime = WorldRuntime.get();
   295→            if (!runtime.isInitialized()) return false;
   296→            WorldDeltaStore store = runtime.deltaStore();
   297→            int x = pos.getX(), y = pos.getY(), z = pos.getZ();
   298→            // Block deltas (CRON-63).
   299→            if (store.hasBlock(x, y, z, Provenance.PLAYER)
   300→                    || store.hasBlock(x, y, z, Provenance.SIMULATION)) return true;
   301→            // Entity placement deltas (CRON-78) — covers player-placed frames
   302→            // (PLACE) and player-removed canon frames (REMOVE). Required so
   303→            // the canon builder skips re-placement when the player directly
   304→            // attacks a canon ItemFrame (no support break, no CRON-76 cascade).
   305→            if (store.hasEntityPlacement(x, y, z, Provenance.PLAYER)
   306→                    || store.hasEntityPlacement(x, y, z, Provenance.SIMULATION)) return true;
   307→            return false;
   308→        } catch (Throwable t) {
   309→            // Defensive: never let a delta-store query failure block a build.
   310→            // Log at debug (not error) to avoid log spam if this fires
   311→            // repeatedly in a broken state.
   312→            Ergenverse.LOGGER.debug("[Ergenverse] Provenance guard failed at {}: {} — proceeding with placement.",
   313→                    pos, t.getMessage());
   314→            return false;
   315→        }
   316→    }

   318→    /**
   319→     * Chunk-scoped build entry point — invoked by the chunk-materializer for
   320→     * each chunk that overlaps the village footprint.
   321→     *
   322→     * <p>When {@code bounds} is non-null, only blocks whose (x, z) fall inside
   323→     * the bounds are placed; the rest are skipped by {@link #sb}. When
   324→     * {@code bounds} is null, the full village is built (command/login path).
   325→     *
   326→     * <p>This method does NOT call {@link #isAlreadyBuilt} — chunk-scoped
   327→     * placement is naturally incremental: each chunk places its own slice,
   328→     * and re-placing an already-present block with the same state is a
   329→     * harmless no-op. The isAlreadyBuilt guard lives in {@link #build} (the
   330→     * full-build path) to keep command/login calls idempotent.
   331→     */
   332→    public static void buildForChunk(ServerLevel level, @Nullable ChunkBounds bounds) {
   333→        ChunkBounds prev = CURRENT_BOUNDS.get();
   334→        CURRENT_BOUNDS.set(bounds);
   335→        try {
   336→            buildInternal(level);
   337→        } finally {
   338→            if (prev == null) CURRENT_BOUNDS.remove();
   339→            else CURRENT_BOUNDS.set(prev);
   340→        }
   341→    }

   687→    /**
   688→     * Place an {@link ItemFrame} entity at the given position, with the
   689→     * same chunk-filter and provenance guards as {@link #sb}.
   690→     *
   691→     * <p><b>CRON-COMPLETIONIST-71:</b> prior to this round,
   692→     * {@code placeItemFrame} called {@code level.addFreshEntity(frame)}
   693→     * directly, bypassing both the chunk filter and the provenance guard.
   694→     * This had two consequences:
   695→     * <ol>
   696→     *   <li><b>Chunk-filter bypass:</b> a frame at (x+1, y+2, z+1) would
   697→     *       be spawned even when {@code buildForChunk} was building an
   698→     *       unrelated chunk. Item frames are entities, not blocks, so
   699→     *       they don't trigger cascading chunk-loads the way block
   700→     *       placements do — but they still spawn visible duplicates
   701→     *       if multiple chunk-loads in the same footprint each spawn
   702→     *       their own frame.</li>
   703→     *   <li><b>Provenance bypass:</b> if a player broke the frame, the
   704→     *       chunk-materializer would re-spawn it on next chunk-load,
   705→     *       undoing the player's edit. This is the same bug class that
   706→     *       CRON-69's {@code ProvenanceAwareRebuildGuard} fixed for
   707→     *       {@code isAlreadyBuilt}, but it persisted in the per-block
   708→     *       chunk-scoped path for entity placements.</li>
   709→     * </ol>
   710→     *
   711→     * <p>The fix mirrors {@code sb()}'s two guards:
   712→     * <ol>
   713→     *   <li><b>Chunk filter:</b> if {@link #CURRENT_BOUNDS} is non-null
   714→     *       and (x, z) falls outside the bounds, skip the spawn.</li>
   715→     *   <li><b>Provenance guard:</b> if {@link #CURRENT_BOUNDS} is
   716→     *       non-null and a PLAYER or SIMULATION delta exists at {@code pos},
   717→     *       skip the spawn — the player (or simulation) has edited this
   718→     *       position, and re-spawning the frame would undo that edit.</li>
   719→     * </ol>
   720→     *
   721→     * <p><b>Limitation:</b> the provenance guard checks the BLOCK position
   722→     * of the frame, not the entity's existence. If a player breaks the
   723→     * frame but leaves the underlying block intact (e.g., the wall block
   724→     * the frame was attached to), the guard correctly fires (the frame
   725→     * break is recorded as a PLAYER delta at the frame's position). If a
   726→     * player breaks the underlying block, the frame is removed by Minecraft
   727→     * automatically, and the block-break delta is at the BLOCK position
   728→     * (not the frame position) — the frame's provenance guard would NOT
   729→     * fire, and the frame would be re-spawned on next chunk-load (since
   730→     * the block was re-placed by the chunk-materializer's block path).
   731→     * This is a known limitation; the fix would require recording a
   732→     * PLAYER delta at the frame position when the frame is removed by
   733→     * block-break cascade. Deferred to a future round.
   734→     *
   735→     * <p><b>Full-build path:</b> when {@link #CURRENT_BOUNDS} is null
   736→     * (full-build path — {@link #build}, called by SpawnEventHandler and
   737→     * ErgenverseCommand), no filtering or guarding occurs. This matches
   738→     * {@code sb()}'s behavior: the full-build path does NOT consult the
   739→     * delta store, because (a) at server-start there are no player deltas
   740→     * yet, and (b) the {@code /ergenverse build} command explicitly wants
   741→     * a full rebuild regardless of player edits.
   742→     */
   743→    private static void placeItemFrame(ServerLevel level, BlockPos pos,
   744→                                          Direction facing, ItemStack item) {
   745→        ChunkBounds b = CURRENT_BOUNDS.get();
   746→        if (b != null) {
   747→            // Guard 1: chunk filter.
   748→            if (!b.contains(pos.getX(), pos.getZ())) return;
   749→            // Guard 2: provenance-aware rebuild guard.
   750→            if (hasPlayerOrSimulationDelta(pos)) return;
   751→        }
   752→        ItemFrame frame = new ItemFrame(level, pos, facing);
   753→        frame.setItem(item);
   754→        level.addFreshEntity(frame);
   755→    }
