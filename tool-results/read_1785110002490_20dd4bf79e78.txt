    42→/**
    43→ * BlueprintChunkGenerator — a true algorithmically-independent chunk generator
    44→ * for Planet Suzaku whose surface terrain is derived from the
    45→ * {@link PlanetSuzakuBlueprint}'s canon geography (plus a tiny deterministic
    46→ * value-noise perturbation seeded by {@link DeterministicSeedHandler#CANON_SEED}),
    47→ * <em>not</em> from {@code minecraft:overworld} noise.
    48→ *
    49→ * <h2>CRON-COMPLETIONIST-60 — TRUE ALGORITHMIC INDEPENDENCE (point 10)</h2>
    50→ *
    51→ * <p>The CRON-71 design (this class's prior form) only wrapped
    52→ * {@link NoiseBasedChunkGenerator} and overrode {@link #getBaseHeight} to add
    53→ * canon terrain offsets on top of vanilla noise. The surface shape was still
    54→ * determined by {@code minecraft:overworld} noise — only nudged a few blocks
    55→ * per canon location. That was a "noise with offset" generator, not a "blueprint"
    56→ * generator. It failed the architectural goal of point 10: <i>"Terrain columns
    57→ * come from the blueprint+layers, not minecraft:overworld noise."</i>
    58→ *
    59→ * <p>This version (CRON-COMPLETIONIST-60) closes that gap:
    60→ * <ul>
    61→ *   <li>{@link #fillFromNoise} is overridden to fill each column from
    62→ *       {@link #canonSurfaceHeight(int, int)}, a pure deterministic function
    63→ *       of the blueprint's canon locations + {@link DeterministicSeedHandler#CANON_SEED}.</li>
    64→ *   <li>{@link #getBaseHeight} returns {@link #canonSurfaceHeight(int, int)}.</li>
    65→ *   <li>{@link #getBaseColumn} returns a column built from
    66→ *       {@link #canonSurfaceHeight(int, int)} — bedrock at the bottom, stone
    67→ *       up to the canon surface, water up to sea level, air above.</li>
    68→ * </ul>
    69→ *
    70→ * <p>The wrapped {@link NoiseBasedChunkGenerator} is still used for
    71→ * {@link #applyCarvers} (caves/ravines) and {@link #buildSurface} (grass/sand/
    72→ * snow/etc. biome surface rules). Those methods use vanilla's noise-derived
    73→ * carving and surface data, which is independent of the surface heightmap —
    74→ * they carve <i>through</i> whatever stone we placed, and apply surface rules
    75→ * on top of whatever stone surface we placed. This preserves caves, ores
    76→ * (ores are placed by feature decoration which queries existing stone), and
    77→ * biome surface variation for free.
    78→ *
    79→ * <p><b>Canon-driven surface formula:</b>
    80→ * <pre>{@code
    81→ *   canonSurfaceHeight(x, z) =
    82→ *       BASE_HEIGHT (64, one above sea level)
    83→ *     + sum_over_nearby_canon_locations(getTerrainWarpForLocation(loc)
    84→ *                                        * linearDecayFactor(distance, RADIUS=200))
    85→ *     + canonNoiseVariation(x, z)   // bilinear value noise, 8-block period,
    86→ *                                    // amplitude ±8, seeded by CANON_SEED
    87→ * }</pre>
    88→ *
    89→ * <h2>CRON-COMPLETIONIST-91 — BLUEPRINT+LAYERS INTEGRATION (point 10 full fidelity)</h2>
    90→ *
    91→ * <p>The CRON-60 design (this class's prior form) derived surface terrain from
    92→ * {@link PlanetSuzakuBlueprint} canon geography alone. That closed the
    93→ * "algorithmic independence from {@code minecraft:overworld} noise" gap, but
    94→ * left a deeper architectural promise unfulfilled: <i>"Terrain columns come
    95→ * from the blueprint+<b>layers</b>, not minecraft:overworld noise."</i>
    96→ *
    97→ * <p>The <b>layers</b> in that promise are the {@link CompositeWorldLayer}'s
    98→ * {@link WorldLayer}s — specifically the {@link Provenance#PLAYER} and
    99→ * {@link Provenance#SIMULATION} layers, which hold the journal of every
   100→ * block change since day 0. Before CRON-91, those layers were only consulted
   101→ * by {@link dev.ergenverse.runtime.materialize.PlanetSuzakuChunkMaterializer#onChunkLoad}
   102→ * — <b>deferred by 1 tick</b> to avoid mutating a chunk during its own assembly.
   103→ * The result: when a player walked back to a previously-edited area and the
   104→ * chunk regenerated from the canon base, there was a 1-tick window (50ms) where
   105→ * the player saw the unedited canon terrain <i>before</i> their PLAYER deltas
   106→ * were re-applied. A visible "flash of unedited terrain."
   107→ *
   108→ * <p>CRON-91 closes that gap. {@link #fillFromNoise} now does a <b>two-phase
   109→ * fill</b>:
   110→ * <ol>
   111→ *   <li><b>Phase 1 — canon base terrain.</b> Bedrock, stone up to
   112→ *       {@link #canonSurfaceHeight}, water up to {@link #SEA_LEVEL}, air above.
   113→ *       Unchanged from CRON-60.</li>
   114→ *   <li><b>Phase 2 — layer override.</b> If {@link WorldRuntime#get()} is
   115→ *       initialized, iterate {@link CompositeWorldLayer#layersInMaterializationOrder()}
   116→ *       and for each non-CANON layer, apply that layer's
   117→ *       {@link ChunkContribution#blockChanges} directly to the chunk via
   118→ *       {@link ChunkAccess#setBlockState}. This is safe during chunk-gen
   119→ *       (uses {@code isMoving=false}, no lighting/tick updates) and is
   120→ *       <b>idempotent</b> — {@code PlanetSuzakuChunkMaterializer.onChunkLoad}
   121→ *       will re-apply the same deltas 1 tick later as a safety net for the
   122→ *       chunk-from-disk reload path, where {@code fillFromNoise} does not fire.</li>
   123→ * </ol>
   124→ *
   125→ * <p><b>Why CANON structures are NOT built during {@code fillFromNoise}:</b>
   126→ * the {@link dev.ergenverse.runtime.materialize.StructureBuilderRegistry} builders
   127→ * need a live {@link net.minecraft.server.level.ServerLevel} (for entity spawns,
   128→ * heightmap resolution, etc.), but {@code fillFromNoise} only has a
   129→ * {@link ChunkAccess} (no level). CANON structure building stays in the
   130→ * materializer. PLAYER/SIMULATION block changes have no such dependency — they
   131→ * are pure (x, y, z, blockState) tuples — so they're safe to apply here.
   132→ *
   133→ * <p>The result: Heng Yue Mountain is always raised +30 near (4200, -1400),
   134→ * the Sea of Devils is always lowered −30 near (6000, -1184), Wang Family
   135→ * Village sits at +8 above sea level on a hill, etc. — every playthrough,
   136→ * regardless of vanilla noise seed. The hand-placed spawn at (3842, -1184)
   137→ * always lands on the same hill. This is <i>true algorithmic independence</i>
   138→ * from {@code minecraft:overworld} noise.
   139→ *
   140→ * <p><b>Codec &amp; registration:</b> Registered as {@code ergenverse:blueprint}
   141→ * via {@link ErgenverseChunkGenerators#BLUEPRINT}. The dimension JSON at
   142→ * {@code data/ergenverse/dimension/planet_suzaku.json} references the generator
   143→ * type as {@code ergenverse:blueprint} with {@code settings: minecraft:overworld}
   144→ * (the overworld settings are used for cave/surface-rule configuration, NOT for
   145→ * surface terrain shape — that comes from this generator).
   146→ *
   147→ * <p><b>Canon fidelity (fact-checked against 仙逆):</b>
   148→ * <ul>
   149→ *   <li>恒岳山 (Heng Yue Mountain): Zhao Country's largest mountain, raised +30.</li>
   150→ *   <li>修魔海 (Sea of Devils): vast perilous sea east of Zhao, lowered −30 → ocean.</li>
   151→ *   <li>朱雀墓 (Suzaku Tomb): underground inheritance site, surface depressed −12.</li>
   152→ *   <li>Wang Family Village: "赵国某偏僻小山村" — remote mountain village, raised +8.
   153→ *       <b>Mod-original naming:</b> canon attests only "赵国某偏僻小山村"
   154→ *       (a remote mountain village in Zhao Country); the name "Wang Family
   155→ *       Village" / "王氏村" is the mod's authoring choice for that canon
   156→ *       location. The raised +8 elevation reflects the "mountain village"
   157→ *       canon description.</li>
   158→ *   <li>藤家城 (Teng Family City): powerful family city in Zhao, raised +10.</li>
   159→ *   <li>雪域国 (Snow Domain): cold elevated country, raised +10.</li>
   160→ *   <li>恒岳派 / 炼魂宗 / 玄道宗 / 洛河门: mountain sects, raised +12 to +15.</li>
   161→ * </ul>
   162→ *
   163→ * <p><b>Known trade-offs (hyper-analytical self-critique):</b>
   164→ * <ul>
   165→ *   <li>The base noise variation is bilinear value noise (8-block period,
   166→ *       ±8 amplitude). This is intentionally crude — its purpose is to break
   167→ *       the perfectly-flat plateau that pure canon warping would produce
   168→ *       between canon locations, NOT to mimic natural terrain. Real terrain
   169→ *       variety now comes from biome-aware profiles (CRON-93) AND biome
   170→ *       surface rules (grass/sand/snow) applied by {@link #buildSurface}.</li>
   171→ *   <li>Caves are carved by vanilla carvers, which use vanilla noise to
   172→ *       determine WHERE to carve. Because our surface is canon-shaped (not
   173→ *       vanilla-noise-shaped), caves may occasionally carve into air (above
   174→ *       our surface where vanilla expected stone) or fail to carve (below our
   175→ *       surface where vanilla expected air). The net effect: caves still
   176→ *       exist but their density/surface-entrance distribution may differ
   177→ *       from a vanilla world. This is acceptable — the canon world has caves,
   178→ *       they just don't align with vanilla noise.</li>
   179→ *   <li>Ores are placed by feature decoration, which queries existing stone
   180→ *       blocks. Since we fill stone up to the canon surface, ores will be
   181→ *       placed normally. No loss here.</li>
   182→ *   <li>Aquifers (underground water) are part of vanilla noise generation.
   183→ *       Skipping vanilla {@code fillFromNoise} means we lose aquifers. This
   184→ *       is a known limitation; aquifers are mostly invisible to the player
   185→ *       (underground water pools) and the Sea of Devils already provides
   186→ *       surface water via our canon fill.</li>
   187→ *   <li>The wrapped generator's {@link NoiseBasedChunkGenerator#fillFromNoise}
   188→ *       is NOT called, so {@code chunk.getOrCreateNoiseChunk(...)} will be
   189→ *       lazily computed on first access (by {@code applyCarvers} or
   190→ *       {@code buildSurface}). This is fine — vanilla supports lazy
   191→ *       NoiseChunk computation.</li>
   192→ * </ul>
   193→ *
   194→ * <h2>CRON-COMPLETIONIST-93 — BIOME-AWARE TERRAIN PROFILES</h2>
   195→ *
   196→ * <p>The CRON-60/91 design derived surface height from canon geography +
   197→ * a flat ±8 fine noise, ignoring the biome entirely. A column in a
   198→ * {@code zhao_mountains} biome got the SAME surface height (Y=64 ± noise)
   199→ * as a column in a {@code zhao_plains} biome. This was a major visual
   200→ * regression from vanilla {@code minecraft:noise}, where mountains rise
   201→ * to Y=120+ and plains stay at Y=64. The world looked like a flat plateau
   202→ * with occasional canon-warped bumps — not a real cultivation world with
   203→ * mountains, plains, oceans, and valleys.
   204→ *
   205→ * <p>CRON-93 closes this gap by adding a {@link BiomeTerrainProfile}
   206→ * lookup to the height computation. The new
   207→ * {@link #biomeAwareSurfaceHeight(int, int, RandomState)} samples the biome
   208→ * source at (x, z) via {@link BiomeSource#getNoiseBiome}, looks up the
   209→ * profile for that biome, and uses the profile's base height + amplitude
   210→ * as the primary determinant of surface shape. Canon warps and fine noise
   211→ * still apply on top.
   212→ *
   213→ * <p><b>New formula (CRON-93):</b>
   214→ * <pre>{@code
   215→ *   biomeAwareSurfaceHeight(x, z) =
   216→ *       biomeProfile.baseHeight                  // plains=64, mountains=110, ocean=35
   217→ *     + biomeAmplitudeNoise(x, z, amplitude)     // ±amplitude, period 24
   218→ *     + canonTerrainOffset(x, z)                 // ±30 from canon locations
   219→ *     + canonNoiseVariation(x, z)                // ±8 fine noise (period 8)
   220→ *     clamped to [2, 256]
   221→ * }</pre>
   222→ *
   223→ * <p>The legacy static {@link #canonSurfaceHeight(int, int)} is RETAINED
   224→ * as a fallback for contexts where no {@link RandomState} is available
   225→ * (e.g., early chunk-gen race, non-Suzaku levels). It returns the
   226→ * pre-CRON-93 height (base 64 + canon warp + fine noise). Structure
   227→ * builders that have a {@link net.minecraft.server.level.ServerLevel}
   228→ * should call the new {@link #surfaceHeightFor(ServerLevel, int, int)}
   229→ * instead, which delegates to the biome-aware instance method.
   230→ *
   231→ * <h2>CRON-COMPLETIONIST-104 — CANON-AWARE CAVE PLACEMENT</h2>
   232→ *
   233→ * <p>The CRON-60/91/93 design derived surface terrain from canon geography
   234→ * + biome profiles, but left {@link #applyCarvers} as a thin delegate to
   235→ * the wrapped {@link NoiseBasedChunkGenerator}. Vanilla carvers use vanilla
   236→ * noise to decide where to carve caves — they have no awareness of canon
   237→ * geography. The result: vanilla caves could carve through the Suzaku Tomb
   238→ * (朱雀墓 — the sacred underground inheritance site of the 朱雀子 lineage),
   239→ * under Wang Family Village (王家村 — Wang Lin's birthplace), under Heng
   240→ * Yue Sect (恒岳派 — Wang Lin's first sect), and under every other
   241→ * settlement/sect/ruin. This was a <b>canon-fidelity violation</b>: those
   242→ * sites are canonically sealed, constructed, or sacred — caves undermine
   243→ * their foundations and break immersion.
   244→ *
   245→ * <p>CRON-104 closes this gap by overriding {@link #applyCarvers} with the
   246→ * {@link #shouldSuppressCarvers} guard. When the chunk's (x, z) bounding
   247→ * box intersects any protected canon location's suppression circle, the
   248→ * carver call is skipped entirely — no caves, no ravines, no canyons.
   249→ * Protected categories: {@code settlement} (7 locations), {@code sect}
   250→ * (4 locations), {@code ruin} (1 location: Suzaku Tomb with extended
   251→ * radius). Unprotected: {@code region}, {@code geographic},
   252→ * {@code dangerous_region} (caves remain active — they are part of the
   253→ * canon geography in those areas).
   254→ *
   255→ * <p>Suppression radii: 80 blocks default (covers a 5-chunk radius around
   256→ * the structure center), 150 blocks for the Suzaku Tomb (the largest,
   257→ * most sacred underground site). The check is a fast rectangle-circle
   258→ * intersection test — O(num_protected_locations) per chunk, currently
   259→ * 12 distance checks per chunk. Negligible cost.
   260→ *
   261→ * <p>The {@link #addDebugScreenInfo} now reports the cave-suppression
   262→ * status at the player's position ("Cave suppression: ACTIVE near
   263→ * Heng Yue Sect (r=80)" or "Cave suppression: inactive"), so the player
   264→ * can verify the canon-fidelity guard is working.
   265→ *
   266→ * <p>MC 1.20.1 / Forge 47.4.0 / Java 17.</p>
   267→ */

   414→    @Override

   418→
   419→    /**
   420→     * Fill the chunk with canon-derived terrain.
   421→     *
   422→     * <p>This is the heart of the algorithmic independence: surface height
   423→     * per column comes from {@link #canonSurfaceHeight(int, int)}, NOT from
   424→     * vanilla noise. The wrapped {@link NoiseBasedChunkGenerator#fillFromNoise}
   425→     * is NOT called — we generate terrain entirely from canon geography.
   426→     *
   427→     * <p>Vanilla {@link #applyCarvers} and {@link #buildSurface} will lazily
   428→     * compute the {@code NoiseChunk} they need for cave placement and surface
   429→     * rules; those operations do NOT depend on the surface heightmap that
   430→     * {@code fillFromNoise} would have produced.
   431→     */
   432→    @Override
   433→    public CompletableFuture<ChunkAccess> fillFromNoise(Executor executor, Blender blender,
   434→                                                           RandomState randomState,
   435→                                                           StructureManager structureManager,
   436→                                                           ChunkAccess chunk) {
   437→        int minY = chunk.getMinBuildHeight();
   438→        int maxY = chunk.getMaxBuildHeight();
   439→        int minChunkX = chunk.getPos().getMinBlockX();
   440→        int minChunkZ = chunk.getPos().getMinBlockZ();
   441→
   442→        // ── Phase 1: canon base terrain (bedrock / stone / water / air) ──
   443→        // Cache block states — BlockState lookup is cheap but de-virtualized
   444→        // local refs are still marginally faster in a hot loop.
   445→        final BlockState stone = Blocks.STONE.defaultBlockState();
   446→        final BlockState water = Blocks.WATER.defaultBlockState();
   447→        final BlockState bedrock = Blocks.BEDROCK.defaultBlockState();
   448→
   449→        // MutableBlockPos avoids per-block allocation. setBlockState on a
   450→        // ProtoChunk during chunk-gen does NOT trigger lighting/scheduled
   451→        // tick updates — it just writes the section state.
   452→        BlockPos.MutableBlockPos pos = new BlockPos.MutableBlockPos();
   453→
   454→        for (int localX = 0; localX < 16; localX++) {
   455→            for (int localZ = 0; localZ < 16; localZ++) {
   456→                int worldX = minChunkX + localX;
   457→                int worldZ = minChunkZ + localZ;
   458→                // CRON-93: biome-aware height (mountains=110, plains=64,
   459→                // ocean=35, etc.) — replaces the flat canonSurfaceHeight.
   460→                // Falls back to legacy static if randomState is null.
   461→                int surfaceHeight = biomeAwareSurfaceHeight(worldX, worldZ, randomState);
   462→
   463→                for (int y = minY; y < maxY; y++) {
   464→                    BlockState state;
   465→                    if (y == minY) {
   466→                        state = bedrock;
   467→                    } else if (y < surfaceHeight) {
   468→                        state = stone;
   469→                    } else if (y < SEA_LEVEL) {
   470→                        state = water;
   471→                    } else {
   472→                        // Air — leave the section's default (air). Skip
   473→                        // setBlockState to avoid 65K useless writes per
   474→                        // column above the surface.
   475→                        continue;
   476→                    }
   477→
   478→                    pos.set(worldX, y, worldZ);
   479→                    chunk.setBlockState(pos, state, false);
   480→                }
   481→            }
   482→        }
   483→
   484→        // ── Phase 2: apply PLAYER + SIMULATION layer overrides (CRON-91) ──
   485→        // The architectural promise in point 10 is "terrain columns come from
   486→        // the blueprint+LAYERS" — not just the blueprint. Before CRON-91, the
   487→        // PLAYER/SIMULATION layers were only consulted by the chunk materializer
   488→        // on ChunkEvent.Load (deferred 1 tick), causing a visible flash of
   489→        // unedited canon terrain when a player walked back to a previously-edited
   490→        // area. Applying the layer overrides directly during fillFromNoise closes
   491→        // that 1-tick window: the player sees their edits immediately when the
   492→        // chunk first becomes visible.
   493→        //
   494→        // Safety:
   495→        //   - chunk.setBlockState(pos, state, false) is the SAME write path
   496→        //     vanilla's NoiseBasedChunkGenerator.fillFromNoise uses; it writes
   497→        //     the section state without triggering lighting/tick updates.
   498→        //   - This is NOT the same as level.setBlock(pos, state, UPDATE_ALL),
   499→        //     which is what the materializer defers to avoid. We are writing
   500→        //     to the ProtoChunk during its own assembly — exactly what
   501→        //     fillFromNoise is designed to do.
   502→        //   - Idempotent with the materializer: setting the same block to the
   503→        //     same state is a no-op. The materializer is still needed for the
   504→        //     chunk-from-disk reload path (where fillFromNoise does NOT fire).
   505→        //   - CANON structures (c.structures) are intentionally NOT built here
   506→        //     — StructureBuilderRegistry builders need a live ServerLevel, but
   507→        //     fillFromNoise only has a ChunkAccess. CANON stays in the materializer.
   508→        applyLayerOverrides(chunk, pos);
   509→
   510→        // Synchronous fill — return already-completed future. Vanilla's
   511→        // NoiseBasedChunkGenerator runs fillFromNoise on a worker thread via
   512→        // supplyAsync(executor); we don't need to because our fill is
   513→        // CPU-bound and fast (no noise sampling, no aquifer computation).
   514→        return CompletableFuture.completedFuture(chunk);
   515→    }

   517→    /**
   518→     * Apply PLAYER and SIMULATION layer overrides to a chunk during fillFromNoise.
   519→     *
   520→     * <p>For each non-CANON layer in {@link CompositeWorldLayer#layersInMaterializationOrder()},
   521→     * queries {@link WorldLayer#getChunkContribution(int, int)} and applies any
   522→     * {@link BlockChangeDelta}s directly to the chunk via
   523→     * {@link ChunkAccess#setBlockState}. This is the CRON-91 upgrade that makes
   524→     * "terrain columns come from the blueprint+LAYERS" literally true — the
   525→     * layer journal is consulted during chunk-gen, not deferred to ChunkEvent.Load.
   526→     *
   527→     * <p><b>No-op when:</b>
   528→     * <ul>
   529→     *   <li>{@link WorldRuntime#get()} is not yet initialized (race during
   530→     *       server start — the runtime binds to the level on ServerStartingEvent,
   531→     *       which may fire AFTER the initial spawn chunks generate). In this
   532→     *       case, the materializer's onChunkLoad will apply the deltas 1 tick
   533→     *       later as a fallback.</li>
   534→     *   <li>The chunk has no PLAYER or SIMULATION deltas (the common case —
   535→     *       most chunks are unedited). The contribution is empty and the loop
   536→     *       is a near-noop.</li>
   537→     * </ul>
   538→     *
   539→     * @param chunk the chunk being assembled (Phase 1 base terrain already placed)
   540→     * @param pos   a reusable MutableBlockPos (avoids per-delta allocation)
   541→     */
   542→    private void applyLayerOverrides(ChunkAccess chunk, BlockPos.MutableBlockPos pos) {
   543→        // Defensive: WorldRuntime may not be initialized yet during the very
   544→        // first chunk-gen pass at server start. The materializer will catch up.
   545→        WorldRuntime runtime;
   546→        try {
   547→            runtime = WorldRuntime.get();
   548→            if (!runtime.isInitialized()) return;
   549→        } catch (Throwable t) {
   550→            Ergenverse.LOGGER.debug("[Ergenverse] BlueprintChunkGenerator: WorldRuntime unavailable during fillFromNoise — deferring layer overrides to materializer. Reason: {}",
   551→                    t.getMessage());
   552→            return;
   553→        }
   554→
   555→        CompositeWorldLayer worldLayer = runtime.worldLayer();
   556→        if (worldLayer == null) return;
   557→
   558→        int chunkX = chunk.getPos().x;
   559→        int chunkZ = chunk.getPos().z;
   560→
   561→        // Iterate in materialization order: CANON first → SIMULATION → PLAYER.
   562→        // PLAYER wins on conflict (applied last). CANON layer's c.structures
   563→        // are skipped (need a live ServerLevel — materializer handles those).
   564→        for (WorldLayer layer : worldLayer.layersInMaterializationOrder()) {
   565→            if (layer.provenance() == Provenance.CANON) continue;
   566→
   567→            ChunkContribution contribution;
   568→            try {
   569→                contribution = layer.getChunkContribution(chunkX, chunkZ);
   570→            } catch (Throwable t) {
   571→                Ergenverse.LOGGER.debug("[Ergenverse] BlueprintChunkGenerator: layer {} getChunkContribution failed for chunk ({},{}): {}",
   572→                        layer.provenance(), chunkX, chunkZ, t.getMessage());
   573→                continue;
   574→            }
   575→            if (contribution == null || contribution.isEmpty()) continue;
   576→
   577→            for (BlockChangeDelta delta : contribution.blockChanges) {
   578→                BlockState state = resolveBlockState(delta.blockState());
   579→                if (state == null) continue;
   580→                pos.set(delta.x(), delta.y(), delta.z());
   581→                chunk.setBlockState(pos, state, false);
   582→            }
   583→        }
   584→    }

   721→    /**
   722→     * Determine whether cave carvers should be suppressed for the given
   723→     * chunk. Returns true iff the chunk's (x, z) bounding box intersects
   724→     * any protected canon location's suppression circle.
   725→     *
   726→     * <p>The check is a fast rectangle-circle intersection test: for each
   727→     * protected location, find the closest point on the chunk's bounding
   728→     * box to the location's center, then check if the squared distance is
   729→     * within the squared radius. This is O(num_protected_locations) per
   730→     * chunk — currently 12 protected locations, so 12 distance checks per
   731→     * chunk. Negligible cost.
   732→     *
   733→     * <p><b>No Y-axis filter:</b> the suppression is per-column, not
   734→     * per-block. The Suzaku Tomb at y=-60 protects ALL carve steps in the
   735→     * chunk column above and around it — the entire (x, z) footprint is
   736→     * sealed. This is correct because vanilla carvers operate per-chunk
   737→     * with a Y range, and we want to seal the entire column to prevent
   738→     * any cave from breaching the sacred chamber.
   739→     *
   740→     * @param chunk the chunk about to be carved
   741→     * @return true iff carvers should be skipped for this chunk
   742→     */
   743→    private boolean shouldSuppressCarvers(ChunkAccess chunk) {
   744→        int chunkMinX = chunk.getPos().getMinBlockX();
   745→        int chunkMaxX = chunk.getPos().getMaxBlockX();
   746→        int chunkMinZ = chunk.getPos().getMinBlockZ();
   747→        int chunkMaxZ = chunk.getPos().getMaxBlockZ();
   748→
   749→        PlanetSuzakuBlueprint blueprint = PlanetSuzakuBlueprint.canonical();
   750→        for (PlanetSuzakuBlueprint.CanonLocation loc : blueprint.allLocations().values()) {
   751→            if (!isProtectedCategory(loc.category)) continue;
   752→            int radius = getCaveSuppressionRadius(loc);
   753→            // Closest point on the chunk's (x, z) bounding box to the
   754→            // location's center, then check squared distance.
   755→            int closestX = Math.max(chunkMinX, Math.min(loc.x, chunkMaxX));
   756→            int closestZ = Math.max(chunkMinZ, Math.min(loc.z, chunkMaxZ));
   757→            int dx = loc.x - closestX;
   758→            int dz = loc.z - closestZ;
   759→            if (dx * dx + dz * dz <= radius * radius) {
   760→                return true;
   761→            }
   762→        }
   763→        return false;
   764→    }

  1013→    /**
  1014→     * Compute the biome-aware surface height at (worldX, worldZ), the
  1015→     * authoritative height function used by {@link #fillFromNoise},
  1016→     * {@link #getBaseHeight}, {@link #getBaseColumn}, and (via
  1017→     * {@link #surfaceHeightFor}) structure builders.
  1018→     *
  1019→     * <p>Formula (CRON-93):
  1020→     * <pre>{@code
  1021→     *   biomeProfile.baseHeight                  // plains=64, mountains=110, ocean=35
  1022→     *     + biomeAmplitudeNoise(x, z, amplitude) // ±amplitude, period 24
  1023→     *     + canonTerrainOffset(x, z)             // ±30 from canon locations
  1024→     *     + canonNoiseVariation(x, z)            // ±8 fine noise (period 8)
  1025→     *     clamped to [2, 256]
  1026→     * }</pre>
  1027→     *
  1028→     * <p>The biome is sampled at (worldX, worldZ) via
  1029→     * {@link BiomeSource#getNoiseBiome} using the {@link RandomState}'s
  1030→     * {@link RandomState#sampler() climate sampler}. The quart Y is
  1031→     * {@link #BIOME_SAMPLE_QUART_Y} (sea level), ensuring we get the surface
  1032→     * biome, not a cave or high-altitude variant.
  1033→     *
  1034→     * <p><b>Fallback behavior:</b> if {@code randomState} is {@code null}, or
  1035→     * the biome lookup fails for any reason, this method falls back to the
  1036→     * legacy {@link #canonSurfaceHeight(int, int)} (no biome awareness).
  1037→     * This ensures robustness during edge cases (early chunk-gen race,
  1038→     * non-Suzaku levels) at the cost of biome-blind height.
  1039→     *
  1040→     * @param worldX      the world X coordinate
  1041→     * @param worldZ      the world Z coordinate
  1042→     * @param randomState the world's random state (provides the climate sampler);
  1043→     *                    may be {@code null} for fallback behavior
  1044→     * @return the biome-aware surface height, clamped to [2, 256]
  1045→     */
  1046→    public int biomeAwareSurfaceHeight(int worldX, int worldZ, RandomState randomState) {
  1047→        // Fallback: no randomState → use legacy static (no biome awareness)
  1048→        if (randomState == null) {
  1049→            return canonSurfaceHeight(worldX, worldZ);
  1050→        }
  1051→
  1052→        BiomeTerrainProfile profile = sampleBiomeProfile(worldX, worldZ, randomState);
  1053→        int offset = getCanonTerrainOffset(worldX, worldZ);
  1054→        int fineNoise = canonNoiseVariation(worldX, worldZ);
  1055→        int biomeNoise = biomeAmplitudeNoise(worldX, worldZ, profile.amplitude());
  1056→
  1057→        int h = profile.baseHeight() + biomeNoise + offset + fineNoise;
  1058→        // Clamp: same [2, 256] bounds as canonSurfaceHeight
  1059→        if (h < 2) return 2;
  1060→        if (h > 256) return 256;
  1061→        return h;
  1062→    }

  1064→    /**
  1065→     * Sample the biome at (worldX, worldZ) and return its terrain profile.
  1066→     *
  1067→     * <p>Uses {@link BiomeSource#getNoiseBiome} with the climate sampler from
  1068→     * {@code randomState}. The quart Y is {@link #BIOME_SAMPLE_QUART_Y}
  1069→     * (sea level). Returns {@link BiomeTerrainProfile#DEFAULT} if the lookup
  1070→     * fails for any reason (defensive — should not occur in practice).
  1071→     */
  1072→    private BiomeTerrainProfile sampleBiomeProfile(int worldX, int worldZ, RandomState randomState) {
  1073→        try {
  1074→            int quartX = worldX >> 2;
  1075→            int quartZ = worldZ >> 2;
  1076→            // In 1.20.1 Mojmaps, RandomState.sampler() returns the Climate.Sampler
  1077→            // used by the multi-noise biome source. Quart resolution is 4 blocks;
  1078→            // quartY = 16 corresponds to world Y = 64 (sea level) — see BIOME_SAMPLE_QUART_Y.
  1079→            Climate.Sampler sampler = randomState.sampler();
  1080→            Holder<Biome> biome = biomeSource.getNoiseBiome(quartX, BIOME_SAMPLE_QUART_Y, quartZ, sampler);
  1081→            if (biome == null) return BiomeTerrainProfile.DEFAULT;
  1082→            return biome.unwrapKey()
  1083→                    .map(key -> BiomeTerrainProfile.forBiome(key.location()))
  1084→                    .orElse(BiomeTerrainProfile.DEFAULT);
  1085→        } catch (Throwable t) {
  1086→            Ergenverse.LOGGER.debug("[Ergenverse] BlueprintChunkGenerator: biome sample failed at ({},{}): {}",
  1087→                    worldX, worldZ, t.getMessage());
  1088→            return BiomeTerrainProfile.DEFAULT;
  1089→        }
  1090→    }

  1147→     * <b>legacy, biome-blind</b> version.
  1148→     *
  1149→     * <p>{@code BASE_SURFACE_HEIGHT + canonTerrainOffset + canonNoiseVariation},

  1151→     * always have at least one stone block above it).

  1179→     *   int surfaceY = BlueprintChunkGenerator.surfaceHeightFor(level, SECT_X, SECT_Z);
  1180→     * }</pre>

  1183→        int offset = getCanonTerrainOffset(worldX, worldZ);
  1184→        int noise = canonNoiseVariation(worldX, worldZ);
  1185→        int h = BASE_SURFACE_HEIGHT + offset + noise;

  1187→        // bedrock + stone). Also never exceed a sane cap to avoid Y=320
  1188→        // pillars on canon warps (current max warp is +30, so the cap is
  1189→        // mostly a defensive measure).
  1190→        if (h < 2) return 2;
  1191→        if (h > 256) return 256;
  1192→        return h;

  1195→    /**
  1196→     * Compute the biome-amplitude noise at (worldX, worldZ) — a bilinear
  1197→     * value noise with period {@link #BIOME_NOISE_PERIOD} and the given
  1198→     * amplitude. Used by {@link #biomeAwareSurfaceHeight} to produce
  1199→     * biome-scale terrain variation (mountain peaks, valley undulations).
  1200→     *
  1201→     * <p>Returns 0 when {@code amplitude <= 0} (no variation needed for
  1202→     * flat biomes like plains, though plains still use amplitude 4 for
  1203→     * gentle rolling).
  1204→     *
  1205→     * <p>The hash function is the same splitmix64 mixer used by
  1206→     * {@link #canonNoiseVariation}, but with a different cell period (24
  1207→     * vs 8), so the two noise layers are decorrelated. Both are seeded by
  1208→     * {@link DeterministicSeedHandler#CANON_SEED}, ensuring determinism.
  1209→     */
  1210→    static int biomeAmplitudeNoise(int worldX, int worldZ, int amplitude) {
  1211→        if (amplitude <= 0) return 0;
  1212→        int cellX = Math.floorDiv(worldX, BIOME_NOISE_PERIOD);
  1213→        int cellZ = Math.floorDiv(worldZ, BIOME_NOISE_PERIOD);
  1214→        int fracX = worldX - cellX * BIOME_NOISE_PERIOD;
  1215→        int fracZ = worldZ - cellZ * BIOME_NOISE_PERIOD;
  1216→
  1217→        // Smoothstep interpolation weights
  1218→        double sx = (double) fracX / BIOME_NOISE_PERIOD;
  1219→        double sz = (double) fracZ / BIOME_NOISE_PERIOD;
  1220→        sx = sx * sx * (3 - 2 * sx);
  1221→        sz = sz * sz * (3 - 2 * sz);
  1222→
  1223→        // Four corner values in range [0, 2*amplitude]
  1224→        double v00 = amplitudeHash(cellX,     cellZ,     amplitude);
  1225→        double v10 = amplitudeHash(cellX + 1, cellZ,     amplitude);
  1226→        double v01 = amplitudeHash(cellX,     cellZ + 1, amplitude);
  1227→        double v11 = amplitudeHash(cellX + 1, cellZ + 1, amplitude);
  1228→
  1229→        double ix0 = v00 + (v10 - v00) * sx;
  1230→        double ix1 = v01 + (v11 - v01) * sx;
  1231→        double val = ix0 + (ix1 - ix0) * sz;
  1232→
  1233→        // Center around zero: range [-amplitude, +amplitude]
  1234→        return (int) Math.round(val - amplitude);
  1235→    }
  1236→
  1237→    /**
  1238→     * Salt value mixed into the amplitude-noise hash to decorrelate it from
  1239→     * the fine-noise hash (so the two noise layers don't produce correlated
  1240→     * values). Arbitrary 64-bit constant; chosen to be distinct from any
  1241→     * multiplier used in {@link #noiseHash}.
  1242→     */
  1243→    private static final long AMPLITUDE_HASH_SALT = 0xA5A5A5A5A5A5A5A5L;
  1244→
  1245→    /**
  1246→     * Deterministic hash for the biome-amplitude noise → value in
  1247→     * [0, 2 * amplitude]. Same splitmix64 mixing as {@link #noiseHash} but
  1248→     * parameterized by amplitude (so different amplitudes produce different
  1249→     * value ranges). Uses {@link #AMPLITUDE_HASH_SALT} to decorrelate from
  1250→     * the fine noise (otherwise the two noise layers would be correlated,
  1251→     * producing unrealistic terrain).
  1252→     */
  1253→    private static long amplitudeHash(int cellX, int cellZ, int amplitude) {
  1254→        long h = DeterministicSeedHandler.CANON_SEED ^ AMPLITUDE_HASH_SALT;
  1255→        h ^= (long) cellX * 0x9E3779B97F4A7C15L;
  1256→        h ^= (long) cellZ * 0xC2B2AE3D27D4EB4FL;
  1257→        h ^= h >>> 33;
  1258→        h *= 0xFF51AFD7ED558CCDL;
  1259→        h ^= h >>> 33;
  1260→        h *= 0xC4CEB9FE1A85EC53L;
  1261→        h ^= h >>> 33;
  1262→        return (h & 0xFFFFFFFFL) % (2L * amplitude + 1);
  1263→    }
  1264→
  1265→    /**
  1266→     * Compute the canon terrain offset at (worldX, worldZ).
  1267→     * Returns the sum of all nearby canon location influences.
  1268→     * Positive = raise terrain (mountain), Negative = lower terrain (sea/tomb).
  1269→     *
  1270→     * <p>Each canon location has an influence that decays linearly from its
  1271→     * center to {@link #TERRAIN_WARP_RADIUS} blocks away. The offset is
  1272→     * deterministic and based on the blueprint's geography.
  1273→     */
  1274→    static int getCanonTerrainOffset(int worldX, int worldZ) {
  1275→        PlanetSuzakuBlueprint blueprint = PlanetSuzakuBlueprint.canonical();
  1276→        int totalOffset = 0;
  1277→
  1278→        for (PlanetSuzakuBlueprint.CanonLocation loc : blueprint.allLocations().values()) {
  1279→            int dx = worldX - loc.x;
  1280→            int dz = worldZ - loc.z;
  1281→            int distSq = dx * dx + dz * dz;
  1282→
  1283→            if (distSq >= TERRAIN_WARP_RADIUS_SQ) continue;
  1284→
  1285→            double dist = Math.sqrt(distSq);
  1286→            double factor = 1.0 - (dist / TERRAIN_WARP_RADIUS);
  1287→
  1288→            int warp = getTerrainWarpForLocation(loc);
  1289→            totalOffset += (int) (warp * factor);
  1290→        }
  1291→
  1292→        return totalOffset;
  1293→    }

  1295→    /**
  1296→     * Compute a small deterministic value-noise variation at (worldX, worldZ).
  1297→     * Bilinear interpolation of a per-cell hash, scaled to ±{@link #NOISE_AMPLITUDE}.
  1298→     * Period = {@link #NOISE_PERIOD} blocks.
  1299→     *
  1300→     * <p>The hash is seeded by {@link DeterministicSeedHandler#CANON_SEED},
  1301→     * so the variation is identical every save. The purpose of this noise is
  1302→     * NOT to mimic natural terrain — it is to break the perfectly-flat plateau
  1303→     * that pure canon warping would produce between canon locations.
  1304→     */
  1305→    static int canonNoiseVariation(int worldX, int worldZ) {
  1306→        int cellX = Math.floorDiv(worldX, NOISE_PERIOD);
  1307→        int cellZ = Math.floorDiv(worldZ, NOISE_PERIOD);
  1308→        int fracX = worldX - cellX * NOISE_PERIOD;
  1309→        int fracZ = worldZ - cellZ * NOISE_PERIOD;
  1310→
  1311→        // Smoothstep interpolation weights
  1312→        double sx = (double) fracX / NOISE_PERIOD;
  1313→        double sz = (double) fracZ / NOISE_PERIOD;
  1314→        sx = sx * sx * (3 - 2 * sx);
  1315→        sz = sz * sz * (3 - 2 * sz);
  1316→
  1317→        // Four corner values in range [0, 2*NOISE_AMPLITUDE]
  1318→        double v00 = noiseHash(cellX,     cellZ);
  1319→        double v10 = noiseHash(cellX + 1, cellZ);
  1320→        double v01 = noiseHash(cellX,     cellZ + 1);
  1321→        double v11 = noiseHash(cellX + 1, cellZ + 1);
  1322→
  1323→        double ix0 = v00 + (v10 - v00) * sx;
  1324→        double ix1 = v01 + (v11 - v01) * sx;
  1325→        double val = ix0 + (ix1 - ix0) * sz;
  1326→
  1327→        // Center around zero: range [-NOISE_AMPLITUDE, +NOISE_AMPLITUDE]
  1328→        return (int) Math.round(val - NOISE_AMPLITUDE);
  1329→    }
  1330→
  1331→    /**
  1332→     * Deterministic hash → value in [0, 2 * NOISE_AMPLITUDE]. Uses a
  1333→     * splitmix64-style mixing of (cellX, cellZ, CANON_SEED) so that
  1334→     * adjacent cells produce decorrelated values.
  1335→     */
  1336→    private static long noiseHash(int cellX, int cellZ) {
  1337→        long h = DeterministicSeedHandler.CANON_SEED;
  1338→        h ^= (long) cellX * 0x9E3779B97F4A7C15L;
  1339→        h ^= (long) cellZ * 0xC2B2AE3D27D4EB4FL;
  1340→        h ^= h >>> 33;
  1341→        h *= 0xFF51AFD7ED558CCDL;
  1342→        h ^= h >>> 33;
  1343→        h *= 0xC4CEB9FE1A85EC53L;
  1344→        h ^= h >>> 33;
  1345→        // Map to [0, 2 * NOISE_AMPLITUDE]
  1346→        return (h & 0xFFFFFFFFL) % (2L * NOISE_AMPLITUDE + 1);
  1347→    }
