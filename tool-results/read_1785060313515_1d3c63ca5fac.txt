    39→/**
    40→ * BlueprintChunkGenerator — a true algorithmically-independent chunk generator
    41→ * for Planet Suzaku whose surface terrain is derived from the
    42→ * {@link PlanetSuzakuBlueprint}'s canon geography (plus a tiny deterministic
    43→ * value-noise perturbation seeded by {@link DeterministicSeedHandler#CANON_SEED}),
    44→ * <em>not</em> from {@code minecraft:overworld} noise.
    45→ *
    46→ * <h2>CRON-COMPLETIONIST-60 — TRUE ALGORITHMIC INDEPENDENCE (point 10)</h2>
    47→ *
    48→ * <p>The CRON-71 design (this class's prior form) only wrapped
    49→ * {@link NoiseBasedChunkGenerator} and overrode {@link #getBaseHeight} to add
    50→ * canon terrain offsets on top of vanilla noise. The surface shape was still
    51→ * determined by {@code minecraft:overworld} noise — only nudged a few blocks
    52→ * per canon location. That was a "noise with offset" generator, not a "blueprint"
    53→ * generator. It failed the architectural goal of point 10: <i>"Terrain columns
    54→ * come from the blueprint+layers, not minecraft:overworld noise."</i>
    55→ *
    56→ * <p>This version (CRON-COMPLETIONIST-60) closes that gap:
    57→ * <ul>
    58→ *   <li>{@link #fillFromNoise} is overridden to fill each column from
    59→ *       {@link #canonSurfaceHeight(int, int)}, a pure deterministic function
    60→ *       of the blueprint's canon locations + {@link DeterministicSeedHandler#CANON_SEED}.</li>
    61→ *   <li>{@link #getBaseHeight} returns {@link #canonSurfaceHeight(int, int)}.</li>
    62→ *   <li>{@link #getBaseColumn} returns a column built from
    63→ *       {@link #canonSurfaceHeight(int, int)} — bedrock at the bottom, stone
    64→ *       up to the canon surface, water up to sea level, air above.</li>
    65→ * </ul>
    66→ *
    67→ * <p>The wrapped {@link NoiseBasedChunkGenerator} is still used for
    68→ * {@link #applyCarvers} (caves/ravines) and {@link #buildSurface} (grass/sand/
    69→ * snow/etc. biome surface rules). Those methods use vanilla's noise-derived
    70→ * carving and surface data, which is independent of the surface heightmap —
    71→ * they carve <i>through</i> whatever stone we placed, and apply surface rules
    72→ * on top of whatever stone surface we placed. This preserves caves, ores
    73→ * (ores are placed by feature decoration which queries existing stone), and
    74→ * biome surface variation for free.
    75→ *
    76→ * <p><b>Canon-driven surface formula:</b>
    77→ * <pre>{@code
    78→ *   canonSurfaceHeight(x, z) =
    79→ *       BASE_HEIGHT (64, one above sea level)
    80→ *     + sum_over_nearby_canon_locations(getTerrainWarpForLocation(loc)
    81→ *                                        * linearDecayFactor(distance, RADIUS=200))
    82→ *     + canonNoiseVariation(x, z)   // bilinear value noise, 8-block period,
    83→ *                                    // amplitude ±8, seeded by CANON_SEED
    84→ * }</pre>
    85→ *
    86→ * <h2>CRON-COMPLETIONIST-91 — BLUEPRINT+LAYERS INTEGRATION (point 10 full fidelity)</h2>
    87→ *
    88→ * <p>The CRON-60 design (this class's prior form) derived surface terrain from
    89→ * {@link PlanetSuzakuBlueprint} canon geography alone. That closed the
    90→ * "algorithmic independence from {@code minecraft:overworld} noise" gap, but
    91→ * left a deeper architectural promise unfulfilled: <i>"Terrain columns come
    92→ * from the blueprint+<b>layers</b>, not minecraft:overworld noise."</i>
    93→ *
    94→ * <p>The <b>layers</b> in that promise are the {@link CompositeWorldLayer}'s
    95→ * {@link WorldLayer}s — specifically the {@link Provenance#PLAYER} and
    96→ * {@link Provenance#SIMULATION} layers, which hold the journal of every
    97→ * block change since day 0. Before CRON-91, those layers were only consulted
    98→ * by {@link dev.ergenverse.runtime.materialize.PlanetSuzakuChunkMaterializer#onChunkLoad}
    99→ * — <b>deferred by 1 tick</b> to avoid mutating a chunk during its own assembly.
   100→ * The result: when a player walked back to a previously-edited area and the
   101→ * chunk regenerated from the canon base, there was a 1-tick window (50ms) where
   102→ * the player saw the unedited canon terrain <i>before</i> their PLAYER deltas
   103→ * were re-applied. A visible "flash of unedited terrain."
   104→ *
   105→ * <p>CRON-91 closes that gap. {@link #fillFromNoise} now does a <b>two-phase
   106→ * fill</b>:
   107→ * <ol>
   108→ *   <li><b>Phase 1 — canon base terrain.</b> Bedrock, stone up to
   109→ *       {@link #canonSurfaceHeight}, water up to {@link #SEA_LEVEL}, air above.
   110→ *       Unchanged from CRON-60.</li>
   111→ *   <li><b>Phase 2 — layer override.</b> If {@link WorldRuntime#get()} is
   112→ *       initialized, iterate {@link CompositeWorldLayer#layersInMaterializationOrder()}
   113→ *       and for each non-CANON layer, apply that layer's
   114→ *       {@link ChunkContribution#blockChanges} directly to the chunk via
   115→ *       {@link ChunkAccess#setBlockState}. This is safe during chunk-gen
   116→ *       (uses {@code isMoving=false}, no lighting/tick updates) and is
   117→ *       <b>idempotent</b> — {@code PlanetSuzakuChunkMaterializer.onChunkLoad}
   118→ *       will re-apply the same deltas 1 tick later as a safety net for the
   119→ *       chunk-from-disk reload path, where {@code fillFromNoise} does not fire.</li>
   120→ * </ol>
   121→ *
   122→ * <p><b>Why CANON structures are NOT built during {@code fillFromNoise}:</b>
   123→ * the {@link dev.ergenverse.runtime.materialize.StructureBuilderRegistry} builders
   124→ * need a live {@link net.minecraft.server.level.ServerLevel} (for entity spawns,
   125→ * heightmap resolution, etc.), but {@code fillFromNoise} only has a
   126→ * {@link ChunkAccess} (no level). CANON structure building stays in the
   127→ * materializer. PLAYER/SIMULATION block changes have no such dependency — they
   128→ * are pure (x, y, z, blockState) tuples — so they're safe to apply here.
   129→ *
   130→ * <p>The result: Heng Yue Mountain is always raised +30 near (4200, -1400),
   131→ * the Sea of Devils is always lowered −30 near (6000, -1184), Wang Family
   132→ * Village sits at +8 above sea level on a hill, etc. — every playthrough,
   133→ * regardless of vanilla noise seed. The hand-placed spawn at (3842, -1184)
   134→ * always lands on the same hill. This is <i>true algorithmic independence</i>
   135→ * from {@code minecraft:overworld} noise.
   136→ *
   137→ * <p><b>Codec &amp; registration:</b> Registered as {@code ergenverse:blueprint}
   138→ * via {@link ErgenverseChunkGenerators#BLUEPRINT}. The dimension JSON at
   139→ * {@code data/ergenverse/dimension/planet_suzaku.json} references the generator
   140→ * type as {@code ergenverse:blueprint} with {@code settings: minecraft:overworld}
   141→ * (the overworld settings are used for cave/surface-rule configuration, NOT for
   142→ * surface terrain shape — that comes from this generator).
   143→ *
   144→ * <p><b>Canon fidelity (fact-checked against 仙逆):</b>
   145→ * <ul>
   146→ *   <li>恒岳山 (Heng Yue Mountain): Zhao Country's largest mountain, raised +30.</li>
   147→ *   <li>修魔海 (Sea of Devils): vast perilous sea east of Zhao, lowered −30 → ocean.</li>
   148→ *   <li>朱雀墓 (Suzaku Tomb): underground inheritance site, surface depressed −12.</li>
   149→ *   <li>Wang Family Village: "赵国某偏僻小山村" — remote mountain village, raised +8.</li>
   150→ *   <li>藤家城 (Teng Family City): powerful family city in Zhao, raised +10.</li>
   151→ *   <li>雪域国 (Snow Domain): cold elevated country, raised +10.</li>
   152→ *   <li>恒岳派 / 炼魂宗 / 玄道宗 / 洛河门: mountain sects, raised +12 to +15.</li>
   153→ * </ul>
   154→ *
   155→ * <p><b>Known trade-offs (hyper-analytical self-critique):</b>
   156→ * <ul>
   157→ *   <li>The base noise variation is bilinear value noise (8-block period,
   158→ *       ±8 amplitude). This is intentionally crude — its purpose is to break
   159→ *       the perfectly-flat plateau that pure canon warping would produce
   160→ *       between canon locations, NOT to mimic natural terrain. Real terrain
   161→ *       variety will come from biome surface rules (grass/sand/snow) applied
   162→ *       by {@link #buildSurface}, not from terrain noise.</li>
   163→ *   <li>Caves are carved by vanilla carvers, which use vanilla noise to
   164→ *       determine WHERE to carve. Because our surface is canon-shaped (not
   165→ *       vanilla-noise-shaped), caves may occasionally carve into air (above
   166→ *       our surface where vanilla expected stone) or fail to carve (below our
   167→ *       surface where vanilla expected air). The net effect: caves still
   168→ *       exist but their density/surface-entrance distribution may differ
   169→ *       from a vanilla world. This is acceptable — the canon world has caves,
   170→ *       they just don't align with vanilla noise.</li>
   171→ *   <li>Ores are placed by feature decoration, which queries existing stone
   172→ *       blocks. Since we fill stone up to the canon surface, ores will be
   173→ *       placed normally. No loss here.</li>
   174→ *   <li>Aquifers (underground water) are part of vanilla noise generation.
   175→ *       Skipping vanilla {@code fillFromNoise} means we lose aquifers. This
   176→ *       is a known limitation; aquifers are mostly invisible to the player
   177→ *       (underground water pools) and the Sea of Devils already provides
   178→ *       surface water via our canon fill.</li>
   179→ *   <li>The wrapped generator's {@link NoiseBasedChunkGenerator#fillFromNoise}
   180→ *       is NOT called, so {@code chunk.getOrCreateNoiseChunk(...)} will be
   181→ *       lazily computed on first access (by {@code applyCarvers} or
   182→ *       {@code buildSurface}). This is fine — vanilla supports lazy
   183→ *       NoiseChunk computation.</li>
   184→ * </ul>
   185→ *
   186→ * <p>MC 1.20.1 / Forge 47.4.0 / Java 17.</p>
   187→ */
   188→public final class BlueprintChunkGenerator extends ChunkGenerator {

   191→     * Codec for deserialization from the dimension JSON. Takes the same
   192→     * fields as {@code minecraft:noise} (biome_source + noise_settings)
   193→     * plus our registry key.
   194→     */
   195→    public static final Codec<BlueprintChunkGenerator> CODEC = RecordCodecBuilder.create(instance ->
   196→            instance.group(
   197→                    BiomeSource.CODEC.fieldOf("biome_source")
   198→                            .forGetter(gen -> gen.biomeSource),
   199→                    NoiseGeneratorSettings.CODEC.fieldOf("settings")
   200→                            .forGetter(gen -> gen.noiseSettings)
   201→            ).apply(instance, BlueprintChunkGenerator::new));

   209→     * <p><b>NOT used for {@code fillFromNoise}</b> — we override that
   210→     * fully to control surface terrain shape from canon geography.
   211→     */

   271→    //  CHUNK GENERATION — TRUE ALGORITHMIC INDEPENDENCE
   272→    // ════════════════════════════════════════════════════════════════════

   274→    @Override
   275→    protected Codec<? extends ChunkGenerator> codec() {
   276→        return CODEC;
   277→    }
   278→
   279→    /**
   280→     * Fill the chunk with canon-derived terrain.
   281→     *
   282→     * <p>This is the heart of the algorithmic independence: surface height
   283→     * per column comes from {@link #canonSurfaceHeight(int, int)}, NOT from
   284→     * vanilla noise. The wrapped {@link NoiseBasedChunkGenerator#fillFromNoise}
   285→     * is NOT called — we generate terrain entirely from canon geography.
   286→     *
   287→     * <p>Vanilla {@link #applyCarvers} and {@link #buildSurface} will lazily
   288→     * compute the {@code NoiseChunk} they need for cave placement and surface
   289→     * rules; those operations do NOT depend on the surface heightmap that
   290→     * {@code fillFromNoise} would have produced.
   291→     */
   292→    @Override
   293→    public CompletableFuture<ChunkAccess> fillFromNoise(Executor executor, Blender blender,
   294→                                                           RandomState randomState,
   295→                                                           StructureManager structureManager,
   296→                                                           ChunkAccess chunk) {
   297→        int minY = chunk.getMinBuildHeight();
   298→        int maxY = chunk.getMaxBuildHeight();
   299→        int minChunkX = chunk.getPos().getMinBlockX();
   300→        int minChunkZ = chunk.getPos().getMinBlockZ();
   301→
   302→        // ── Phase 1: canon base terrain (bedrock / stone / water / air) ──
   303→        // Cache block states — BlockState lookup is cheap but de-virtualized
   304→        // local refs are still marginally faster in a hot loop.
   305→        final BlockState stone = Blocks.STONE.defaultBlockState();
   306→        final BlockState water = Blocks.WATER.defaultBlockState();
   307→        final BlockState bedrock = Blocks.BEDROCK.defaultBlockState();
   308→
   309→        // MutableBlockPos avoids per-block allocation. setBlockState on a
   310→        // ProtoChunk during chunk-gen does NOT trigger lighting/scheduled
   311→        // tick updates — it just writes the section state.
   312→        BlockPos.MutableBlockPos pos = new BlockPos.MutableBlockPos();
   313→
   314→        for (int localX = 0; localX < 16; localX++) {
   315→            for (int localZ = 0; localZ < 16; localZ++) {
   316→                int worldX = minChunkX + localX;
   317→                int worldZ = minChunkZ + localZ;
   318→                int surfaceHeight = canonSurfaceHeight(worldX, worldZ);
   319→
   320→                for (int y = minY; y < maxY; y++) {
   321→                    BlockState state;
   322→                    if (y == minY) {
   323→                        state = bedrock;
   324→                    } else if (y < surfaceHeight) {
   325→                        state = stone;
   326→                    } else if (y < SEA_LEVEL) {
   327→                        state = water;
   328→                    } else {
   329→                        // Air — leave the section's default (air). Skip
   330→                        // setBlockState to avoid 65K useless writes per
   331→                        // column above the surface.
   332→                        continue;
   333→                    }
   334→
   335→                    pos.set(worldX, y, worldZ);
   336→                    chunk.setBlockState(pos, state, false);
   337→                }
   338→            }
   339→        }
   340→
   341→        // ── Phase 2: apply PLAYER + SIMULATION layer overrides (CRON-91) ──
   342→        // The architectural promise in point 10 is "terrain columns come from
   343→        // the blueprint+LAYERS" — not just the blueprint. Before CRON-91, the
   344→        // PLAYER/SIMULATION layers were only consulted by the chunk materializer
   345→        // on ChunkEvent.Load (deferred 1 tick), causing a visible flash of
   346→        // unedited canon terrain when a player walked back to a previously-edited
   347→        // area. Applying the layer overrides directly during fillFromNoise closes
   348→        // that 1-tick window: the player sees their edits immediately when the
   349→        // chunk first becomes visible.
   350→        //
   351→        // Safety:
   352→        //   - chunk.setBlockState(pos, state, false) is the SAME write path
   353→        //     vanilla's NoiseBasedChunkGenerator.fillFromNoise uses; it writes
   354→        //     the section state without triggering lighting/tick updates.
   355→        //   - This is NOT the same as level.setBlock(pos, state, UPDATE_ALL),
   356→        //     which is what the materializer defers to avoid. We are writing
   357→        //     to the ProtoChunk during its own assembly — exactly what
   358→        //     fillFromNoise is designed to do.
   359→        //   - Idempotent with the materializer: setting the same block to the
   360→        //     same state is a no-op. The materializer is still needed for the
   361→        //     chunk-from-disk reload path (where fillFromNoise does NOT fire).
   362→        //   - CANON structures (c.structures) are intentionally NOT built here
   363→        //     — StructureBuilderRegistry builders need a live ServerLevel, but
   364→        //     fillFromNoise only has a ChunkAccess. CANON stays in the materializer.
   365→        applyLayerOverrides(chunk, pos);
   366→
   367→        // Synchronous fill — return already-completed future. Vanilla's
   368→        // NoiseBasedChunkGenerator runs fillFromNoise on a worker thread via
   369→        // supplyAsync(executor); we don't need to because our fill is
   370→        // CPU-bound and fast (no noise sampling, no aquifer computation).
   371→        return CompletableFuture.completedFuture(chunk);
   372→    }
   373→
   374→    /**
   375→     * Apply PLAYER and SIMULATION layer overrides to a chunk during fillFromNoise.
   376→     *
   377→     * <p>For each non-CANON layer in {@link CompositeWorldLayer#layersInMaterializationOrder()},
   378→     * queries {@link WorldLayer#getChunkContribution(int, int)} and applies any
   379→     * {@link BlockChangeDelta}s directly to the chunk via
   380→     * {@link ChunkAccess#setBlockState}. This is the CRON-91 upgrade that makes
   381→     * "terrain columns come from the blueprint+LAYERS" literally true — the
   382→     * layer journal is consulted during chunk-gen, not deferred to ChunkEvent.Load.
   383→     *
   384→     * <p><b>No-op when:</b>
   385→     * <ul>
   386→     *   <li>{@link WorldRuntime#get()} is not yet initialized (race during
   387→     *       server start — the runtime binds to the level on ServerStartingEvent,
   388→     *       which may fire AFTER the initial spawn chunks generate). In this
   389→     *       case, the materializer's onChunkLoad will apply the deltas 1 tick
   390→     *       later as a fallback.</li>
   391→     *   <li>The chunk has no PLAYER or SIMULATION deltas (the common case —
   392→     *       most chunks are unedited). The contribution is empty and the loop
   393→     *       is a near-noop.</li>
   394→     * </ul>
   395→     *
   396→     * @param chunk the chunk being assembled (Phase 1 base terrain already placed)
   397→     * @param pos   a reusable MutableBlockPos (avoids per-delta allocation)
   398→     */
   399→    private void applyLayerOverrides(ChunkAccess chunk, BlockPos.MutableBlockPos pos) {
   400→        // Defensive: WorldRuntime may not be initialized yet during the very
   401→        // first chunk-gen pass at server start. The materializer will catch up.
   402→        WorldRuntime runtime;
   403→        try {
   404→            runtime = WorldRuntime.get();
   405→            if (!runtime.isInitialized()) return;
   406→        } catch (Throwable t) {
   407→            Ergenverse.LOGGER.debug("[Ergenverse] BlueprintChunkGenerator: WorldRuntime unavailable during fillFromNoise — deferring layer overrides to materializer. Reason: {}",
   408→                    t.getMessage());
   409→            return;
   410→        }
   411→
   412→        CompositeWorldLayer worldLayer = runtime.worldLayer();
   413→        if (worldLayer == null) return;
   414→
   415→        int chunkX = chunk.getPos().x;
   416→        int chunkZ = chunk.getPos().z;
   417→
   418→        // Iterate in materialization order: CANON first → SIMULATION → PLAYER.
   419→        // PLAYER wins on conflict (applied last). CANON layer's c.structures
   420→        // are skipped (need a live ServerLevel — materializer handles those).
   421→        for (WorldLayer layer : worldLayer.layersInMaterializationOrder()) {
   422→            if (layer.provenance() == Provenance.CANON) continue;
   423→
   424→            ChunkContribution contribution;
   425→            try {
   426→                contribution = layer.getChunkContribution(chunkX, chunkZ);
   427→            } catch (Throwable t) {
   428→                Ergenverse.LOGGER.debug("[Ergenverse] BlueprintChunkGenerator: layer {} getChunkContribution failed for chunk ({},{}): {}",
   429→                        layer.provenance(), chunkX, chunkZ, t.getMessage());
   430→                continue;
   431→            }
   432→            if (contribution == null || contribution.isEmpty()) continue;
   433→
   434→            for (BlockChangeDelta delta : contribution.blockChanges) {
   435→                BlockState state = resolveBlockState(delta.blockState());
   436→                if (state == null) continue;
   437→                pos.set(delta.x(), delta.y(), delta.z());
   438→                chunk.setBlockState(pos, state, false);
   439→            }
   440→        }
   441→    }

   443→    /**
   444→     * Resolve a registry id string (e.g. {@code "minecraft:stone"}) to a
   445→     * {@link BlockState}. Returns the default block state (no property
   446→     * overrides — the WorldDeltaStore journals block ids, not full state
   447→     * strings, so default state is the correct interpretation). Returns
   448→     * {@code null} for unresolvable ids.
   449→     *
   450→     * <p>Mirrors {@link dev.ergenverse.runtime.layer.WorldFacade#resolveBlockState}
   451→     * — kept private here to avoid pulling WorldFacade into the chunk-gen
   452→     * dependency graph (chunk-gen must remain pure w.r.t. the blueprint and
   453→     * the layer journal, not depend on the facade's live-level mirror logic).
   454→     */
   455→    private static BlockState resolveBlockState(String blockId) {
   456→        if (blockId == null || blockId.isEmpty()) return null;
   457→        try {
   458→            ResourceLocation rl = new ResourceLocation(blockId);
   459→            Block block = ForgeRegistries.BLOCKS.getValue(rl);
   460→            if (block == null) return null;
   461→            return block.defaultBlockState();
   462→        } catch (Throwable t) {
   463→            return null;
   464→        }
   465→    }

   518→    /**
   519→     * Get the surface height at (x, z), derived from canon geography.
   520→     * This is the ONLY method that determines surface terrain shape —
   521→     * {@link #fillFromNoise}, {@link #getBaseHeight}, and
   522→     * {@link #getBaseColumn} all consult this.
   523→     *
   524→     * <p>The height is deterministic: same x, z, CANON_SEED → same result,
   525→     * every save, every chunk load.
   526→     */
   527→    @Override
   528→    public int getBaseHeight(int x, int z, Heightmap.Types heightmap,
   529→                             LevelHeightAccessor level, RandomState randomState) {

   533→    /**
   534→     * Get the base noise column at (x, z), built from canon surface height.
   535→     * Returns bedrock at the bottom, stone up to the canon surface, water
   536→     * up to sea level, air above.
   537→     */
   538→    @Override
   539→    public NoiseColumn getBaseColumn(int x, int z, LevelHeightAccessor level,
   540→                                      RandomState randomState) {
   541→        int minY = level.getMinBuildHeight();
   542→        int height = level.getHeight();
   543→        int surfaceHeight = canonSurfaceHeight(x, z);
   544→
   545→        BlockState[] states = new BlockState[height];
   546→        for (int i = 0; i < height; i++) {
   547→            int y = minY + i;
   548→            if (y == minY) {
   549→                states[i] = Blocks.BEDROCK.defaultBlockState();
   550→            } else if (y < surfaceHeight) {
   551→                states[i] = Blocks.STONE.defaultBlockState();
   552→            } else if (y < SEA_LEVEL) {
   553→                states[i] = Blocks.WATER.defaultBlockState();
   554→            } else {
   555→                states[i] = Blocks.AIR.defaultBlockState();
   556→            }
   557→        }
   558→        return new NoiseColumn(minY, states);
   559→    }

   589→    // ════════════════════════════════════════════════════════════════════
   590→    //  CANON SURFACE HEIGHT — pure deterministic function of (x, z)
   591→    // ════════════════════════════════════════════════════════════════════
   592→
   593→    /**
   594→     * Compute the canon-derived surface height at (worldX, worldZ).
   595→     *
   596→     * <p>{@code BASE_SURFACE_HEIGHT + canonTerrainOffset + canonNoiseVariation},
   597→     * clamped to a non-negative minimum (bedrock layer at {@code minY} must
   598→     * always have at least one stone block above it).
   599→     *
   600→     * <p><b>CRON-COMPLETIONIST-67:</b> this method is now {@code public} so that
   601→     * structure builders can resolve their center Y from the <i>same canon
   602→     * authority</i> that the chunk generator uses — eliminating the heightmap
   603→     * race condition where {@code level.getHeightmapPos(MOTION_BLOCKING_NO_LEAVES, ...)}
   604→     * would return y=0 or a stale value if the chunk at the canon center wasn't
   605→     * loaded yet when {@code buildForChunk} fired for an adjacent chunk. The
   606→     * canon surface height is a pure deterministic function of (x, z) — it does
   607→     * NOT depend on chunk-load state, so it returns the correct Y every time,
   608→     * regardless of which chunks are loaded.
   609→     *
   610→     * <p>Builders should call this instead of {@code level.getHeightmapPos(...)}:
   611→     * <pre>{@code
   612→     *   int surfaceY = BlueprintChunkGenerator.canonSurfaceHeight(SECT_X, SECT_Z);
   613→     *   return new BlockPos(SECT_X, surfaceY, SECT_Z);
   614→     * }</pre>
   615→     */
   616→    public static int canonSurfaceHeight(int worldX, int worldZ) {
   617→        int offset = getCanonTerrainOffset(worldX, worldZ);
   618→        int noise = canonNoiseVariation(worldX, worldZ);
   619→        int h = BASE_SURFACE_HEIGHT + offset + noise;
   620→        // Clamp: never let the surface drop to or below 1 (need at least
   621→        // bedrock + stone). Also never exceed a sane cap to avoid Y=320
   622→        // pillars on canon warps (current max warp is +30, so the cap is
   623→        // mostly a defensive measure).
   624→        if (h < 2) return 2;
   625→        if (h > 256) return 256;
   626→        return h;
   627→    }
   628→
   629→    /**
   630→     * Compute the canon terrain offset at (worldX, worldZ).
   631→     * Returns the sum of all nearby canon location influences.
   632→     * Positive = raise terrain (mountain), Negative = lower terrain (sea/tomb).
   633→     *
   634→     * <p>Each canon location has an influence that decays linearly from its
   635→     * center to {@link #TERRAIN_WARP_RADIUS} blocks away. The offset is
   636→     * deterministic and based on the blueprint's geography.
   637→     */
   638→    static int getCanonTerrainOffset(int worldX, int worldZ) {
   639→        PlanetSuzakuBlueprint blueprint = PlanetSuzakuBlueprint.canonical();
   640→        int totalOffset = 0;
   641→
   642→        for (PlanetSuzakuBlueprint.CanonLocation loc : blueprint.allLocations().values()) {
   643→            int dx = worldX - loc.x;
   644→            int dz = worldZ - loc.z;
   645→            int distSq = dx * dx + dz * dz;
   646→
   647→            if (distSq >= TERRAIN_WARP_RADIUS_SQ) continue;
   648→
   649→            double dist = Math.sqrt(distSq);
   650→            double factor = 1.0 - (dist / TERRAIN_WARP_RADIUS);
   651→
   652→            int warp = getTerrainWarpForLocation(loc);
   653→            totalOffset += (int) (warp * factor);
   654→        }
   655→
   656→        return totalOffset;
   657→    }
   658→
   659→    /**
   660→     * Compute a small deterministic value-noise variation at (worldX, worldZ).
   661→     * Bilinear interpolation of a per-cell hash, scaled to ±{@link #NOISE_AMPLITUDE}.
   662→     * Period = {@link #NOISE_PERIOD} blocks.
   663→     *
   664→     * <p>The hash is seeded by {@link DeterministicSeedHandler#CANON_SEED},
   665→     * so the variation is identical every save. The purpose of this noise is
   666→     * NOT to mimic natural terrain — it is to break the perfectly-flat plateau
   667→     * that pure canon warping would produce between canon locations.
   668→     */
   669→    static int canonNoiseVariation(int worldX, int worldZ) {
   670→        int cellX = Math.floorDiv(worldX, NOISE_PERIOD);
   671→        int cellZ = Math.floorDiv(worldZ, NOISE_PERIOD);
   672→        int fracX = worldX - cellX * NOISE_PERIOD;
   673→        int fracZ = worldZ - cellZ * NOISE_PERIOD;
   674→
   675→        // Smoothstep interpolation weights
   676→        double sx = (double) fracX / NOISE_PERIOD;
   677→        double sz = (double) fracZ / NOISE_PERIOD;
   678→        sx = sx * sx * (3 - 2 * sx);
   679→        sz = sz * sz * (3 - 2 * sz);
   680→
   681→        // Four corner values in range [0, 2*NOISE_AMPLITUDE]
   682→        double v00 = noiseHash(cellX,     cellZ);
   683→        double v10 = noiseHash(cellX + 1, cellZ);
   684→        double v01 = noiseHash(cellX,     cellZ + 1);
   685→        double v11 = noiseHash(cellX + 1, cellZ + 1);
   686→
   687→        double ix0 = v00 + (v10 - v00) * sx;
   688→        double ix1 = v01 + (v11 - v01) * sx;
   689→        double val = ix0 + (ix1 - ix0) * sz;
   690→
   691→        // Center around zero: range [-NOISE_AMPLITUDE, +NOISE_AMPLITUDE]
   692→        return (int) Math.round(val - NOISE_AMPLITUDE);
   693→    }
   694→
   695→    /**
   696→     * Deterministic hash → value in [0, 2 * NOISE_AMPLITUDE]. Uses a
   697→     * splitmix64-style mixing of (cellX, cellZ, CANON_SEED) so that
   698→     * adjacent cells produce decorrelated values.
   699→     */
   700→    private static long noiseHash(int cellX, int cellZ) {
   701→        long h = DeterministicSeedHandler.CANON_SEED;
   702→        h ^= (long) cellX * 0x9E3779B97F4A7C15L;
   703→        h ^= (long) cellZ * 0xC2B2AE3D27D4EB4FL;
   704→        h ^= h >>> 33;
   705→        h *= 0xFF51AFD7ED558CCDL;
   706→        h ^= h >>> 33;
   707→        h *= 0xC4CEB9FE1A85EC53L;
   708→        h ^= h >>> 33;
   709→        // Map to [0, 2 * NOISE_AMPLITUDE]
   710→        return (h & 0xFFFFFFFFL) % (2L * NOISE_AMPLITUDE + 1);
   711→    }

   713→    /**

   715→     * Positive = raise (mountains), Negative = lower (seas/tombs).
   716→     *
